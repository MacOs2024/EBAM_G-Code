# EBAM G-code Studio v2.9 — автономный запуск без интернета

Приложение не использует внешний сервер. Оно запускает локальный сервер на вашем компьютере и открывается в браузере по адресу вида:

```text
http://127.0.0.1:8501
```

Интернет нужен только для первичной установки зависимостей или для сборки переносимой версии. После этого интернет не нужен.

## Вариант 1. На этом же ПК уже всё установлено

Если вы уже один раз запускали приложение через `run_windows_ROBUST.bat` и папка `.venv` создана, можно запускать без интернета:

```bat
run_windows_OFFLINE_EXISTING_VENV.bat
```

Linux:

```bash
./run_linux_OFFLINE_EXISTING_VENV.sh
```

Этот запуск не делает `pip install` и не обращается в интернет.

## Вариант 2. Компьютер без интернета, но Python установлен

На компьютере с интернетом выполните:

```bat
download_wheelhouse_windows.bat
```

Появится папка `wheelhouse` со всеми пакетами. Затем скопируйте всю папку приложения вместе с `wheelhouse` на компьютер без интернета и запустите:

```bat
install_from_wheelhouse_windows.bat
```

Этот способ всё равно требует установленный Python 3.10–3.13 на целевом ПК.

## Вариант 3. Самый удобный: переносимая EXE-папка для Windows

На одном Windows-компьютере с интернетом и Python 3.12 выполните:

```bat
build_windows_portable_exe.bat
```

После сборки появится папка:

```text
dist\EBAM_Gcode_Studio
```

Её можно скопировать на другой Windows-компьютер. На другом компьютере Python и интернет уже не нужны. Запуск:

```text
EBAM_Gcode_Studio.exe
```

Важно: для Windows собирайте на Windows. Linux-сборка не создаст нормальный Windows `.exe`.

## Вариант 4. Переносимая Linux-сборка

На Linux-компьютере с интернетом выполните:

```bash
./build_linux_portable_binary.sh
```

После сборки копируйте папку:

```text
dist/EBAM_Gcode_Studio
```

Запуск:

```bash
./EBAM_Gcode_Studio
```

Для Linux желательно собирать на похожей версии дистрибутива, где будет запускаться приложение.

## Почему нельзя сделать один файл сразу для Windows и Linux

Windows и Linux используют разные исполняемые файлы, разные системные библиотеки и разные загрузчики Python. Поэтому правильная схема такая:

```text
Windows → отдельная Windows-сборка .exe
Linux   → отдельная Linux-сборка
```

Одна и та же исходная программа используется в обоих случаях.

## Рекомендация для цеха/пусконаладки

Для рабочего места оператора лучше использовать вариант 3:

```text
собрать один раз portable EXE → перенести папку на станочный ПК → запускать без интернета и без установки Python
```

Перед промышленным использованием всё равно обязателен сухой прогон G-code без пучка/проволоки и проверка W-ретракта.
