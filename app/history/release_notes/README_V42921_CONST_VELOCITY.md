# EBAM G-Code Studio v4.2.9.21 — CONSTANT-VELOCITY RADIAL COMPENSATION («вариант Б»)
База: v4.2.9.20 TIME LEVERS. Отчёт по стандарту проекта.

## Проблема (реальный файл Flange1_R6, найдена оператором)
При постоянной скорости стола C=599.5 °/мин линейная скорость на ободе растёт с
радиусом (v=C·π·R/180): кольцо R=21 идёт 3.7 мм/с, кольцо R=81 — 13.9 мм/с (×3.75).
Генератор, соблюдая объёмный баланс, разгонял подачу E2 вслед за скоростью:
13.2 → 49.5 мм/с (у предела 50), а ток стоял на 38 мА. Плотность энергии QV падала
104 → 42 Дж/мм³ — проволока переставала успевать плавиться и «лезла из ванны».

## Ключевая формула (почему решение именно такое)
E2 = pitch·z·v/A_wire — радиус сокращается, подача зависит ТОЛЬКО от линейной
скорости v. Значит: держим v постоянной → E2 постоянна → проволока стабильна.

## Решение: режим rotary_c_constant_velocity (трёхзонный профиль)
1) МАЛЫЕ R: чтобы держать целевую v, C нужна выше максимума → C клипуется на max
   (600), v ниже целевой растёт с R, E2 растёт 10→22 (там QV высокая, ванна тянет).
2) СРЕДНИЕ R: C плавно снижается 600→450 (≈2-5% на кольцо — эффект, который
   оператор нащупал вручную), v держится у цели, E2 зафиксирована.
3) ВНЕШНИЕ R: C упёрлась в нижний предел 450 → вместо разгона E2 УПЛОТНЯЕТСЯ ШАГ
   колец (pitch_factor до min_pitch_factor): металла на кольцо меньше → E2 не растёт.
Целевая v выводится из «комфортной E2» (по умолчанию 29 мм/с) через баланс объёма:
v = E2_comfort·A_wire·η/(pitch·z).

## Новые поля ProcessSettings
rotary_c_constant_velocity (False), rotary_c_target_linear_mm_s (0=авто из комфорта),
rotary_c_wire_comfort_mm_s (29.0), rotary_c_shrink_pitch_at_floor (True),
rotary_c_min_pitch_factor (0.5). Плюс функции _rotary_c_target_linear_mm_s() и
_rotary_c_ring_kinematics() → (C, факт.подача, pitch_factor) на кольцо.

## Куда встроено
Три генератора: _generate_mesh_rotary_c (STL), _generate_rotational_shell_rotary_c
(параметрический), no-pause цикл с experience-профилем (зона профиля имеет приоритет
над compensation). Legacy-режим (галочка выключена) байт-в-байт прежний. Попутно
исправлен учёт feed_limited_count в no-pause ветке (считался по уже клипнутому C).

## UI
Блок «Компенсация подачи по радиусу» в настройках C-стола: галочка «Стабилизировать
скорость наплавки по радиусу», поля «Комфортная подача E2» и «Мин. коэффициент
уплотнения шага». Значения применяются к settings в обоих режимах интерфейса.

## Доказательства (профиль Flange1, R 21→81, прогонами)
- E2 в файле: 10.1 → 22.45 мм/с, ДАЛЬШЕ НЕ РАСТЁТ (в R6 было 13 → 49.5, runaway).
- C: 600 (внутр.) → 450 (внешн.), плавное снижение в средней зоне.
- pitch_factor: 1.0 → 0.78 на самом краю (уплотнение вместо разгона E2).
- Разброс E2 по детали ≤2.3× (был 3.75× с упором в предел).
Новый rotary_c_constant_velocity_regression_test: 8 проверок (E2 ограничена, разброс
мал, C монотонно вниз и в лимитах 450–600, уплотнение только на полке, внутри = 1.0,
legacy не изменён, v_target по формуле) — все проходят.
Регрессия: их 9 не-STL наборов + time_target_levers — failures=0.

## Ограничения (честно)
- Реальный G-code Flange1_R7 в среде разработки НЕ сгенерирован: STL-путь требует
  настоящий trimesh (здесь стабы). Генерация — на Windows в v4.2.9.21: включить
  галочку компенсации, комфортная E2 = 29, min pitch factor = 0.6, остальное как в R6.
- Оценщик времени пока моделирует компенсацию приближённо (клип по C на радиус);
  точное время — по фактическим траекториям после генерации.
- Уплотнение шага уменьшает подачу пропорционально, но фактические радиусы колец
  внутри слоя не переупаковываются (шаг сетки прежний, металла кладётся меньше на
  кольцо) — при min_pitch_factor<0.6 проверить перекрытие TEST-кольцом.
- Streamlit UI и STL-тесты — прогнать на Windows.
