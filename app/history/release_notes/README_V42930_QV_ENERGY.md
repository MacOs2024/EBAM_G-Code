# EBAM G-Code Studio v4.2.9.30 — ЭНЕРГИЯ ПО ОБЪЁМУ (QV), А НЕ ПО ДЛИНЕ
База: v4.2.9.29. Разбор реального случая: блок 30x70x30 (файл qwerty123.ngc, 06.08.2026),
где оператору пришлось вручную вести скорость стола, подачу проволоки и ток всю наплавку.

## ПРИЧИНА (доказана расчётом по файлу и по фото пульта)
Профиль материала задавал энергию как 158 Дж/мм — константу, НЕ зависящую от сечения валика.
  сечение валика = высота слоя x шаг дорожек
  QV (Дж/мм³)    = энергия(Дж/мм) / сечение
Одна и та же константа 158 Дж/мм даёт:
  блок  (слой 0.50 x шаг 2.35 = 1.175 мм²) -> QV = 134  ПЕРЕГРЕВ (брызги, волна сверху)
  фланец(слой 1.53 x шаг 2.58 = 3.947 мм²) -> QV =  40  НИЖЕ ПОРОГА ОТКАЗА 42
  тонкий(слой 0.25 x шаг 2.35 = 0.588 мм²) -> QV = 269  испарение
То есть 158 Дж/мм верна ровно для одного сечения ~2.2 мм² и вредна на всех остальных.
Файл оператора: QV = 123..140. Руками он вывел процесс на QV = 83 (подача x1.56, скорость x1.76)
— то есть ровно в полосу 55..90, подтверждённую наплавками R7/R8. Отказ R6 был при QV = 42.

## ЧТО ИСПРАВЛЕНО
1. БИБЛИОТЕКА МАТЕРИАЛОВ переведена на QV (Дж/мм³): нержавейка 72/63, сталь 73/64,
   титан 66/57, бронза 57/50. Старые Дж/мм оставлены как запасной вариант для совместимости.
   Якорь 72 — середина полевой полосы; пропорции между материалами сохранены.
2. РЕКОМЕНДАТОР считает Дж/мм из QV по ФАКТИЧЕСКОМУ сечению валика, после того как
   определены слой и шаг (включая все геометрические поправки). Профиль стал переносимым.
3. СВЯЗЬ С ПОРОГОМ ПРОПЛАВА: P = QV x сечение x скорость. Тонкий слой при правильной QV
   физически не может дать мощность проплава (слой 0.25 -> 460 Вт против порога 900).
   Рекомендатор теперь наращивает высоту слоя, пока мощность не превысит порог,
   в пределах 0.3..1.4 диаметра проволоки. Проверено: все режимы и геометрии дают
   QV 72..76 и мощность >= 900 Вт.
4. ВАЛИДАЦИЯ QV с двух сторон: >= 110 Дж/мм³ — перегрев (блок), <= 42 — непроплав (блок),
   вне 55..90 — предупреждение. Сообщение называет конкретную цифру, куда снижать/поднимать.
5. ДЕФОЛТ ProcessSettings был сам перегрет (слой 0.3, шаг 2.0, 158 Дж/мм -> QV 263).
   Новый дефолт: слой 0.5, шаг 2.35, энергия 84.6/74.0 -> QV 72/63, мощность 916 Вт.
6. СВЕТОФОР РАСШИРЕН НА XY-СТРАТЕГИИ. Раньше он парсил только кольцевые комментарии и на
   штриховке не проверял НИЧЕГО (на файле оператора показывал "колец 0" и жёлтый).
   Теперь читает заголовки слоёв (I, F, WIRE), считает QV и проверяет с обеих сторон.
   На qwerty123.ngc даёт КРАСНЫЙ с точной причиной: "QV 123..140, 60 участков выше 90".
7. ПЛОТНОСТЬ УСТАВОК E0/E2: M68 в LinuxCNC не синхронизирован с движением и рвёт сглаживание
   G64 — станок тормозит на каждой уставке. В файле оператора 4065 M68 на 4061 движение
   (одна на ход). Добавлены: показ этой плотности в светофоре и опция
   "Упростить рампу проволоки" (одна уставка на дорожку вместо трёх).
   Радикальное решение прежнее — перевод на M67 после HAL-кита.
8. СКОРОСТЬ F В ПРОСТОМ РЕЖИМЕ (по запросу): поля "Скорость низ/верх F" плюс живая строка
   плотности энергии под ними — QV, мощность и сечение валика пересчитываются на лету,
   с цветным вердиктом. Ток в простом режиме теперь считается от введённой скорости.
9. Строка QV в сводке получила вердикт ("в норме" / "ПЕРЕГРЕВ" / "НЕ ПРОПЛАВИТ").

## ЧЕСТНЫЕ ОГОВОРКИ
- Полоса QV 55..90 выведена из наплавок нержавейки (R6/R7/R8 + этот блок). Для титана и
  бронзы значения пересчитаны пропорционально и полем НЕ подтверждены — нужен свой TEST.
- Streamlit визуально не запускается в среде разработки: поля скорости, живая строка QV и
  галочка рампы проверены компиляцией и логикой, вид — на Windows.
- Опция упрощения рампы убирает плавный вход/выход валика на концах дорожек: возможны
  наплывы на краях. Включать осознанно и проверять коротким TEST.
