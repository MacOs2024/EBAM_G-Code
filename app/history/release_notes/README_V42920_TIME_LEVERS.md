# EBAM G-Code Studio v4.2.9.20 — TIME-TARGET FIX + SELECTABLE LEVERS
База: v4.2.9.19 (FLANGE FAMILY, из другого чата — исходник предоставлен). Отчёт по стандарту проекта.

## Баг, который чинили (реальный, по скриншоту)
Подстройка под время писала «целевое 5.5 ч, получилось +0.0%», а реальный G-code
выходил на 134 ч. Причина доказана прогонами: оценщик времени в режиме no-pause C
(`_estimate_time_before_generation`, ветка no_pause_flat_rings) моделировал деталь
как ОДНО кольцо на слой (радиус ~80, 219 колец) и игнорировал лимит стола C. Реальный
генератор наплавляет МНОГО концентрических колец на слой (радиальное заполнение
R_вн..R_нар), фактически 4118 колец. Промах ×19. Тюнер «сходился» к своей неверной
оценке и рапортовал +0.0%, хотя реальность в 24 раза больше.

## Что исправлено
1. ОЦЕНЩИК: no-pause C теперь считает реальное число концентрических колец
   = (R_нар − R_вн)/шаг, суммирует время каждого кольца с учётом C-лимита по радиусу
   (малый радиус → выше требуемая C → упор в лимит → медленнее). Проверено: даёт
   десятки/сотни часов вместо минут; монотонно реагирует на все рычаги; при толстом
   слое 2.35 + шаг 4 + быстрый F показывает ~4 ч (совпадает с интуицией оператора).
2. ЧЕСТНЫЙ ВЕРДИКТ: если разрешёнными рычагами в цель не уложиться — пишет «минимально
   достижимо ≈ N ч» и НАЗЫВАЕТ, какие рычаги разрешить. Больше нет ложного «+0.0%».
3. ЗАЩИТА radial_step=0 (перенос из v4.2.9.16): нулевой шаг для ротационной стратегии
   → ошибка с объяснением (чаша вместо диска, кратная высота слоя, неверное время).
   Плюс проверка эффективного шага <0.3 и >20 мм.

## Новое: ВЫБИРАЕМЫЕ РЫЧАГИ регулировки времени (по запросу)
В разделе «Целевое время» — выбор, что программе можно менять, каждый рычаг с галочкой
и жёстким пределом:
- Высота слоя (макс. мм)     — выше слой → меньше слоёв → быстрее
- Шаг колец / ширина (макс. мм) — шире → меньше колец → быстрее
- Скорость стола C (макс. °/мин) — быстрее вращение → быстрее
- Ток пучка E0 (макс. мА)    — выше ток → можно быстрее с проплавом
Зафиксированный рычаг НЕ трогается (пиннится на базовом значении). E2 (проволока)
ВСЕГДА зависимая — считается из объёма (высота×шаг×скорость), чтобы не было переподачи,
которая испортила прошлые детали (Cylindr_V5, Flange_V1 с ручным E2=10). Всё физически
связано: нельзя выдать нереальный режим.

## Ограничения (честно)
- Оценщик работает ДО генерации, поэтому радиус детали берётся из габаритов (bounding
  box), а не из точных STL-сечений — оценка в пределах ~10-20% от факта, но БЕЗ прежнего
  24-кратного вранья. Точное время — после генерации по фактическим траекториям.
- STL-тесты (flange_family_regression_test и др.) требуют реальный STL/trimesh и в этой
  среде не запускались — правки их не касаются, прогнать на Windows.
- Streamlit UI-тесты требуют streamlit — прогнать на Windows.
- E2 всегда зависимая (по договорённости): если нужен ручной E2 как рычаг — отдельная задача.
