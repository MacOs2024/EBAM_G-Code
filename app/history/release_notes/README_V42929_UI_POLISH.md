## Пункт 3 — Симулятор по слоям с раскраской по QV (вкладка «Предпросмотр»)
Блок «🎞️ Симулятор по слоям»: загружаешь G-code → ползунок «Слой» → концентрические
кольца слоя раскрашены по плотности энергии QV: КРАСНЫЙ ≤42 Дж/мм³ (полевой порог отказа,
где проволока лезла из ванны в R6) → ЗЕЛЁНЫЙ = комфорт. Под графиком — зона, Z, число колец
и предупреждение, если min QV слоя ≤46.5. Ловит опасные слои и зарастание ГЛАЗАМИ до станка.
Работает для C-стратегий с кольцевыми комментариями; для XY — единый бакет колец.
Бэкенд: gcode_tools.layer_ring_profile() (на реальном R8: 32 слоя, QV 46.2..103.6, худший
слой №1 min 46.2 — совпадает с ручным разбором).

## Пункт 7 — Живые подсказки у полей
Под полем «Шаг дорожек» (расширенный режим) — строка: «при валике ~X мм это TOM-перекрытие
26%; валиков на 100 мм: N». Число обретает смысл на месте (та самая путаница «0.6 мм или доля»).

## Пункт 8 — Хлебные крошки этапов
Под заголовком: «Этапы: 1·STL/режим → 2·параметры → 3·проверка → 4·TEST → 5·файл».
Ориентир, где ты в процессе; дополняет FOCUS-режим.

## Пункт 9 — Дребезг пересчёта (ЧЕСТНО)
Полноценный input-debounce требует фронтенда Streamlit и в этой среде не реализуется/не
тестируется без риска. Частично уже решено в v4.2.9.25: перевод полей на ключи session_state
сделал их «липкими» и убрал сброс на каждом пересчёте — визуального дёрганья заметно меньше.
Дальнейший debounce (если будет мешать) — отдельная задача с проверкой на Windows.
