# EBAM G-Code Studio

Генератор и аудитор управляющих программ (G-code) для электронно-лучевой проволочной
наплавки на установке **«Бормаш»** под управлением LinuxCNC.

**Текущая версия: v4.2.9.31**

ООО «ФабМеталл», Томск. Разработка и пусконаладка — М. Керенцев.

---

## Что делает программа

Превращает 3D-модель детали (STL) или набор простых геометрических параметров в
управляющую программу, рассчитывая при этом технологический режим: траекторию движения
поворотного стола, ток электронного луча и скорость подачи присадочной проволоки.

- Расчёт G-code по STL или по параметрам (цилиндр, диск, чаша, фланец, пластина и др.)
- Стратегии: XY-штриховка, змейка, концентрические кольца, спираль, кольца на поворотном столе C
- Подбор режима под заданное время изготовления с честным вердиктом о достижимости
- Автоматическая проверка готовой программы перед отправкой на станок
- Послойный просмотр с раскраской по плотности энергии
- Профили режимов и журнал наплавок

## Физические основы

Три модели, выведенные и подтверждённые на реальных наплавках. Подробности — в
[инструкции](docs/) и в заметках к версиям (`app/history/release_notes/`).

### 1. Плотность энергии по объёму (QV)

Ключевая величина процесса — **энергия на объём наплавленного металла**, Дж/мм³:

```
QV = U · I / (A_проволоки · E2 · η)     [Дж/мм³]
QV = энергия(Дж/мм) / (высота слоя × шаг дорожек)
```

Энергия на длину (Дж/мм) сама по себе о перегреве ничего не говорит: одна и та же
константа 158 Дж/мм даёт QV = 134 на тонком валике (перегрев, брызги) и QV = 40 на
толстом (ниже порога отказа). Полоса, подтверждённая наплавками:

| QV, Дж/мм³ | Что происходит |
|---|---|
| ≤ 42 | проволока перестаёт плавиться и выходит из ванны (отказ R6) |
| 55–90 | **рабочая полоса** (подтверждена R7, R8 и блоком 30×70×30) |
| ≥ 110 | перегрев, разбрызгивание, волнистая поверхность |

Мощность луча связана с этим напрямую: `P = QV × сечение валика × скорость`. Отсюда
следствие: слишком тонкий слой при правильной QV физически не даёт мощность проплава.

### 2. Компенсация подачи по радиусу (constant velocity)

При постоянной скорости поворотного стола линейная скорость на ободе растёт с радиусом
(`v = C·π·R/180`), и подача проволоки разгоняется вслед за ней. Из объёмного баланса:

```
E2 = шаг · высота слоя · v / A_проволоки      (радиус сокращается!)
```

Подача зависит только от линейной скорости. Отсюда трёхзонный алгоритм: на малых
радиусах стол на максимуме, на средних скорость стола плавно снижается, удерживая
линейную скорость постоянной, на внешних (стол упёрся в нижний предел) уплотняется шаг
между кольцами. Результат: подача остаётся в комфортной полосе по всей детали.

### 3. Адаптивная тепловая выдержка

Слои разной длины остывают по-разному. Если слой наплавляется быстрее заданного
минимального цикла, в конец добавляется пауза:

```
выдержка = max(мин. цикл − время слоя, минимальная выдержка)
```

Длинные слои (диск) получают ноль, короткие (ступица) — паузу на остывание.

### 4. Зависимость от диаметра проволоки

QV от диаметра не зависит, но всё остальное пересчитывается автоматически:

| Ø, мм | Сечение, мм² | Потолок подачи при 40 мА | Границы слоя, мм |
|---|---|---|---|
| 1.2 | 1.131 | 39.8 мм/с | 0.36–1.68 |
| 1.6 | 2.011 | 22.4 мм/с | 0.48–2.24 |
| 2.0 | 3.142 | 14.3 мм/с | 0.60–2.80 |
| 2.5 | 4.909 | 9.2 мм/с | 0.75–3.50 |

Ограничение подачи задаёт **луч, а не механизм**: он плавит не более `U·I/QV` мм³/с,
и толстая проволока даёт этот объём при меньшей линейной подаче.

> Полем подтверждён только Ø1.2 мм. Профили 1.6/2.0/2.5 требуют калибровочного валика.

## Установка и запуск

### Windows (рабочий вариант)

```
run_windows.bat
```

Или вручную:

```bash
pip install -r app/requirements.txt
cd app
streamlit run app.py
```

Откроется окно браузера по адресу `127.0.0.1:8501`.

Подробности: `app/README_WINDOWS_INSTALL.txt`, офлайн-установка — `app/README_OFFLINE_RU.md`.

### Проверка после изменений

```bash
cd app
python tests/qv_energy_regression_test.py
python tests/wire_diameter_regression_test.py
python tests/rotary_c_constant_velocity_regression_test.py
python tests/thermal_dwell_regression_test.py
```

Все наборы печатают JSON; `failures: []` означает, что проверки пройдены.

## Порядок допуска файла к наплавке

Обязателен для каждой новой программы:

1. Сгенерировать G-code, проверить светофор (вкладка «Генерация»)
2. Убедиться в отсутствии красных отметок
3. Открыть программу в просмотрщике LinuxCNC
4. **Сухой прогон без луча и без проволоки**
5. Проверить работу W-оси (отвод проволоки)
6. Наплавить короткий TEST-файл (10–15 мм)
7. Замерить TEST и сверить с расчётом
8. Только теперь — полная деталь

Подробно — в разделе 6 руководства оператора.
